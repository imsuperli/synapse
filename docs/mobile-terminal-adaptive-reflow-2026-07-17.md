# 手机终端按视口重排：问题与实现记录

## 问题

远程手机终端此前把电脑 PTY 的完整 `cols x rows` 网格等比铺满手机高度。电脑窗口较宽时，手机只能看到一行的一部分，需要频繁横向拖动；字体缩放只是放大整个电脑网格，不会按手机宽度重新换行。

电脑终端的一条物理行不能直接作为手机的一条物理行：电脑窗口可以随时改变宽度。手机应展示相同的逻辑内容，并按手机当前可用宽度、字体大小重新生成视觉行。

## 不能直接修改的边界

- 手机不能调用远程 PTY resize。共享 PTY 的尺寸属于电脑端，修改会同时影响电脑界面和正在运行的程序。
- 不能直接在手机列数上回放电脑 PTY 原始字节。光标定位、清屏、滚动区域和备用屏指令都依赖电脑网格。
- 不能通过同一个 xterm 在电脑尺寸和手机尺寸间机械往返。真实 xterm 测试确认：光标位于屏幕中部时可能裁掉光标后的内容；即使光标位于末尾，也可能丢失尾部空格并改变后续写入位置。
- 不能把任意 TUI 当作普通文本重新换行。vim、top、Codex 动态界面和鼠标模式需要保留源网格。

## 本轮实现

新增远程专用 `mobile-reflow` 展示模式，并保持已有 `font-size`、`viewport-zoom` 行为不变。

### 标准模型

- 原始 PTY 字节始终先由电脑 `cols x rows` 的 xterm 标准模型解析。
- 标准模型负责 ANSI、光标、模式、备用屏和鼠标状态，不把手机尺寸反馈给电脑。
- 自适应视图激活后，标准模型只保留电脑当前屏幕和少量上下文，避免长期保存两份 30,000 行历史。

### 手机投影

- 普通、稳定的 normal buffer 从标准模型序列化后，在手机列数上重新生成。
- 字体大小决定手机列数和行数；双指缩放完成后重新投影，而不是拉伸字形。
- 普通追加输出直接增量写入手机投影，避免每个输出块都全量重建。
- 复杂控制序列、备用屏、鼠标模式或光标位于内容中部时自动使用电脑原始布局。
- 备用屏和 TUI 回退保持源网格、按高度铺满且可横向平移，不再把几百列压成极小字。
- 动态界面结束并恢复为稳定 normal buffer 后，由 React Native 已保存的完整历史触发一次原子重建，再返回自适应布局。
- 被历史分页、缩放或重连取消的旧重建会统一回收，不残留重复 surface。

### 兼容性约束

- 历史分页、`history-top` 手势门槛、旧 surface 原子替换和 3 秒边界提示保持不变。
- 键盘输入仍发送到同一个电脑 PTY；备用屏和鼠标报告只在源网格布局中启用。
- 选择、复制、URL/文件点击继续基于当前可见 xterm。
- OSC 8 链接在安全增量输出中原样保留；全量投影会同步重建链接范围。

## 已知语义边界

- xterm 的软换行可以按手机宽度重新流动。
- 应用主动输出的硬换行不会被猜测合并。程序若按电脑宽度主动插入换行，手机仍保留这些换行。
- 旧历史没有完整的电脑 resize 时间线，只能按当前快照尺寸恢复；协议后续应增加带输出序号的 resize 事件。

## 回归验证

- `228 x 70` 电脑网格在普通输出下生成约 40-50 列的手机视图，不再默认横向溢出。
- 1、1.25、1.5、2 倍字体均重新计算手机列数，内容不因缩放丢失。
- 备用屏、鼠标模式和中部光标自动保留源网格。
- 快速连续初始化、延迟写回调、裸 LF/tab、OSC 8 链接坐标和复杂输出静默恢复均有回归覆盖。
- 历史到顶只在有效下拉抬手后触发；历史激活期间旧 surface 保持可见。
- 原有 CSI S scrollback、OSC 链接、文件点击、选择、键盘、重连和前后台恢复测试继续通过。
